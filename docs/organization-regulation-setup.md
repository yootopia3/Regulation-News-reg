# 직제규정 기준 전환

## 변경 내용
직제규정(organization)의 조문별 조직명 목록을 검토한 후 사용한다. 운영 worker는 활성 직제규정만 읽는다.
업무분장규정과 업무분석서는 보관할 수 있으나 분석 입력으로 전송하지 않는다. 직제규정이 없으면 분석하지 않는다.
부서명은 검토한 조직명에서만 선택한다. 관련 업무, 점검 질문, 요청 증빙은 AI의 추정이다.
보고서 및 Excel에 추정 안내를 표시한다. 기존 초안에서 추정 표식을 제거한 게시 요청은 거부한다.
직제규정도 비공개 원문으로 취급한다. AI는 조직 목록이 있는 검토 조문만 입력받으며 원문 인용은 관리자 초안에만 남긴다.

## 운영 적용 순서
1. GitHub Actions 변수 SANCTION_AUTOMATION_ENABLED를 false로 두고 실행 중 분석이 끝난 뒤 전환한다.
2. Supabase SQL Editor에서 db/migrations/202609180001_organization_basis.sql 전체를 실행한다.
   **이 단계에서 기존 업무분장규정 기준 분석 결과와 게시본은 무효화된다.** 문서 원본은 삭제하지 않는다.
3. GitHub Desktop에서 변경을 커밋/Push하고 Vercel의 최신 배포가 Ready인지 확인한다.
4. /admin/documents에서 문서 종류 ‘직제규정’을 선택하고 HWP를 등록한다.
5. 로컬에서 `.venv\Scripts\python.exe -m src.services.internal_documents.worker --once`를 실행한다.
6. 문서 검토 화면에서 각 조문의 조직명을 확인한다. 자동 후보에는 누락이나 일반 명칭이 있을 수 있다.
   한 줄에 하나씩 원문에 있는 조직명을 입력한다. 조직 목록 없는 조문은 비운다. 원문 밖 이름은 저장할 수 없다.
   제6조 본부 조직, 제7~9조 영업·국외 조직을 특히 확인한다. 전체 검토를 저장한 후 활성화한다.
7. 관리자 분석 화면에서 국민은행 등 기존 공시를 ‘다시 분석’한다. 기존 작업을 자동으로 재분석해 과금하지 않는다.
8. worker/자동 workflow 실행 후 직제규정 기반 추정 안내, 부서명, 업무/점검 질문을 확인한다.
9. SANCTION_AUTOMATION_ENABLED=true로 복구한다. 이후 신규 대상은 기존 자동 분석·검증·게시 흐름을 사용한다.

## 확인이 필요한 결과
조직 후보가 없거나 AI가 판단하지 못한 지적사항은 자동 게시하지 않고 검토 대상으로 남긴다.
분석 후보는 최대 12개 조직 목록 조문, 합계 24,000자이며 초과 시 조용히 자르지 않고 검토 오류를 반환한다.
같은 종류의 새 직제규정을 활성화하거나 삭제하면 이전 버전 결과는 무효화된다.

## 키 관리
앞서 화면에 노출된 OpenAI 키, Supabase 서버 키 및 자동화 토큰은 운영 재개 전에 교체한다.
키를 채팅, Git, 문서에 붙여 넣지 않는다. Supabase 레거시 JWT 키 교체는 기존 클라이언트 영향부터 확인한다.
