# 업무원장 분석의 사건 맥락 및 부서 선정 검토

## 목적과 범위
주말 업무원장 통합을 유지하면서 요약에서 누락된 사건 맥락이 부서 선정에 영향을 주는 문제를 보완한다. 부서 수를 강제하거나 특정 은행 사례에 맞춘 부서를 코드에 넣지 않는다.

## 설계
- 업무원장 경로의 공개 사실 추출 프롬프트에 거래 유형·의심 계기·경고 전달·당사자별 대응·확인된 위반과 예방 권고 구분을 명시한다. 기존 Finding/공개 보고서 형식은 유지한다.
- 두 번째 단계에 요약과 함께 전체 공개 페이지를 전달한다. 기존 원장 축약 정보만 사용하고 파일 경로·출처 원문은 추가로 전송하지 않는다. 120,000자 요청 한도를 유지해 초과 시 오류로 중단한다.
- AI는 matches 외에 검토한 유사 후보의 포함/제외/판단 유보, 업무 ID, 적용대상, 역할, 판단 이유, 공개 공시 근거를 반환한다. 모든 73개 부서에 억지 판단을 생성하지 않으며 특정 3개 부서를 강제하지 않는다.
- 서버가 업무 ID·동일 부서·중복·포함 판단과 matches의 정확한 일치·공개 근거 인용을 검사한다. 이는 의미적 적합성을 입증하는 검사는 아니며 관리자 확인이 필요하다.
- 판단 기록은 private result.department_assessments에만 추가하고 관리자 화면에서 확인한다. 공개 DTO/Excel에는 포함하지 않는다. 기존 결과의 필드 누락은 허용한다.

## 작업 순서
1. 현재 revision 25 국민은행 검토본과 활성 원장 로컬 백업 완료. 운영 DB에는 쓰지 않는다.
2. 분석 코드·관리자 표시·합성 사례 회귀 테스트·문서를 수정한다.
3. Python, 웹 검증 및 별도 검토를 완료한다.
4. 사용자가 승인한 공개 공시와 축약 업무원장을 사용해 같은 모델로 단건 비교 분석한다. 결과는 Git 밖 로컬 파일에만 저장한다. 이전 운영 검토본과 비교하고 기존 상태가 보존됐는지 확인한다.
5. 내용 검토 후 Commit/Push 및 운영 재분석은 별도 후속 단계다. 게시·전체 자동화 활성화·DB migration 재실행은 범위 밖이다.

## 수용 기준
요약 축약 여부와 무관하게 원문이 매칭 단계에 전달된다. 업무 선정·판단 기록이 모순되거나 근거가 원문과 다르면 거부한다. 공개 게시 projection에 비공개 판단 기록이 유출되지 않는다. 실제 국민은행의 해외송금·무역거래 의심·경고·업체별 대응을 기존 결과와 비교한다.

## 2026-09-22 저장 응답 검증
실제 AI 응답은 같은 부서의 고객확인 업무를 포함하고 다른 보고 업무를 유보했다. 이를 부서 수준 중복으로 거부하던 조건을 업무 수준으로 수정했다. 동일 지적사항·업무의 중복/상충은 거부하고, 포함 업무 전체와 matches 업무 전체의 일치를 유지한다. UI에서는 같은 부서 아래 업무별 판단을 표시한다.

추가 API 호출 없이 저장 응답 그대로 재검증 통과: 지적사항 1개, 자금세탁방지부 업무 2개 포함, 같은 부서 보고업무 유보, 여신기획부·준법지원부 검토업무 제외. 해외송금·허위 무역거래 의심·경고 전달·B와 D/E 대응 차이를 요약에 포함했다. 외환지원부·외환사업부 판단 기록은 누락되어 내용상 완결성은 아직 확인되지 않았다. 운영 검토본에 반영하지 않았다. 이번 변경의 Python 27개와 웹 4개 검사 통과.
