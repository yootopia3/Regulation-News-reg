# Stage C 검토·게시

관리자 초안 조회에 공개용 편집·저장·게시·철회를 추가한다. 일반 사용자는
Report 하위 메뉴에서 게시된 snapshot만 보고 XLSX를 내려받는다.

1. 게시 DTO에는 지적사항 ID/제목/요약/부서/관련 업무/점검 질문·증빙/공개 페이지 번호만 허용한다.
2. 수정 저장과 게시를 분리하고 revision으로 충돌을 차단한다. 게시 때 전체 지적사항
   포함 여부·페이지 번호·내부 인용 복사를 검사하고 관리자 확인을 요구한다.
3. 별도 service_role 전용 게시 테이블에 snapshot을 기록한다. 일반 API는 서명 세션 확인,
   공개 DTO 재검증·명시적 projection·private,no-store를 적용한다.
4. 수정 저장·재분석·규정 변경·삭제 시 게시본을 자동 철회하고 snapshot을 지운다.
   행위 이력에는 내용 대신 ID·행위·revision·담당자·시각만 남긴다.
5. 일반 화면은 게시본만 읽고 XLSX도 같은 조회 경로를 사용한다. 내부 근거/문서 ID와
   수식·숨은 시트·외부 링크는 내보내지 않는다.
6. DB 수명주기·권한·누출 canary·수식 방지·UI·회귀 테스트와 독립 검토를 수행한다.

자동 문자열 검사는 재서술한 기밀 여부를 보장하지 못하므로 관리자가 공개 범위를
검토한다. 실제 migration, 운영 설정, 게시 행위는 이번 코드 구현과 별개다.

검증 완료: 웹 117개 테스트, 세 migration 통합 DB 테스트, ESLint,
Next.js production build 통과. 독립 검토에서 지적한 출처 식별을
공시 제목·원문 링크·Excel 출처 열로 보완했다. 운영 적용은 미실행이다.
