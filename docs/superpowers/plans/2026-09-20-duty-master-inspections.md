# 공시내규 업무원장 기반 제재 분석

## 문제와 설계

현재 worker는 활성 직제규정의 조직 목록만으로 담당부서와 업무를 추정한다.
사용자가 작성한 본부 업무원장을 분석 기준으로 사용하고 영업조직을 제외한다.
공개 제재 사실의 요약과 당행의 예방 점검 제안을 계속 분리한다.

- 기존 두 단계 분석 중 공개 지적사항 추출은 유지한다.
- 비공개 업무원장을 별도 버전 데이터로 등록한다. 원문·로컬 경로·실제
  조직 데이터는 저장소에 넣지 않는다. CLI로 사용자 JSON을 검증·등록한다.
- 활성 업무원장이 있으면 해당 버전만 작업 의존성으로 사용한다. 없으면
  기존 직제규정 경로를 유지한다. 등록과 활성화는 분리하며 migration만으로
  기존 결과를 무효화하지 않는다.
- 축약 업무원장 전체를 한 번 제공하고 AI가 지적사항별 업무 ID를 선택한다.
  짧은 업무 설명의 어휘 차이 때문에 관련 부서가 검색에서 누락되지 않도록 한다.
  요청 한도를 넘으면 일부를 조용히 잘라내지 않고 관리자 검토로 중단한다.
  부서명과 근거 수준은 모델의 자유 문자열이 아니라 업무원장에서 결정한다.
- 명시/내용 추정/자료 부족을 보고서와 Excel에서도 보존한다. 원장에 명시된
  업무라도 해당 제재와의 관련성은 AI 제안이며 당행의 위반 사실이 아니다.
- 원장 교체는 기존 문서와 같은 버전·lease·게시 무효화 경계를 사용한다.
  자료 부족만으로 연결된 초안은 자동 게시 대상에서 제외한다.

## 구현 순서

1. 검증 가능한 원장 DTO, 변환 CLI, 비공개 저장·활성화 migration과 회귀시험.
2. 전체 업무 후보·분석·응답 검증과 worker 연결. 원장 근거 수준·업무 ID 보존.
3. 게시 DTO 검증, 화면·Excel의 업무 근거 표시 및 기존 보고서 호환시험.
4. Python/web/DB 검사와 별도 검토 pass, 발견사항 수정.
5. 사용자 지정 기존 공시로 시범 분석과 비교. 실제 원문·계정 접근이 필요하다.

## 운영 적용

SQL·원장 활성화·배포는 준비된 결과를 확인한 뒤 수행한다. 원장 활성화는
이전 기준 초안·게시본을 무효화하므로 운영 적용 전에 그 영향을 안내한다.
새 기능 구현은 외부 알림 전송이나 기존 공시 전체 재분석을 포함하지 않는다.
