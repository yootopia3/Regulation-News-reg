# 직제규정 조직 선택 오류 수정

기존 직제규정 전환 계획의 국소 보완이다. 운영 분석에서 저장된 조직 목록은 유효했지만 AI가 반환한 부서명이 선택 조문의 목록에 없어 `invalid_department`로 두 번 중단됐다.

## 선택한 방식
부서명과 조문을 별도로 생성하는 대신 검토된 (조문 ref, 조직명) 쌍에 요청 내 ID를 부여한다. Structured Output은 해당 ID만 허용하며 서버가 기존 초안의 부서명/ref를 복원한다. 자유 입력 정규화나 유사 이름 치환은 잘못된 부서를 승인할 수 있어 사용하지 않는다.

## 구현 및 검증
1. 기존 공통 분석 필드 모델을 재사용하고 조직 선택 응답에만 동적 ID enum을 적용한다.
2. 조문 원문은 기존처럼 한 번만 전송한다. 공개/비공개 근거, 중복 부서, 전체 지적사항 처리, 원문 유출 검증을 유지한다.
3. 저장 결과, DB, 웹 API 계약은 변경하지 않는다. 프롬프트 버전은 organization-v2로 올린다.
4. 허용 목록 외 ID 차단, 다른 조문에 있는 부서 선택, 잘못된 근거 조문 차단, 중복 차단, 후보 한도 및 기존 분석 경로를 테스트한다.
5. 별도 검토 후 승인된 국민은행 작업으로 실제 결과를 확인한다. 사용자가 GitHub Desktop에서 Commit/Push하기 전에는 Actions 코드에 반영되지 않는다.

실제 재분석에서 조직 선택 이후 AI의 원문 인용도 `invalid_internal_evidence`로 거절됐다. 조직 선택 응답에서는 인용 생성을 제거하고, 서버가 선택한 조직명이 있는 원문 구간(최대 300자)을 그대로 붙인다. 이는 조직 구성의 근거이며 상세 업무의 근거라는 의미는 아니다. 만들어진 인용도 기존 원문 일치·조직명 포함 검증을 거친다. 정확한 인용 구간을 만들 수 없는 경우 계속 차단한다.

운영 재시도는 기존에 승인된 동일 자료/대상에 한정하며 결과의 부서 추정 및 근거 검증을 우회하지 않는다.

## 검증 결과
- 관련 Python 테스트 67개 통과, 별도 코드 검토 완료.
- 활성 직제규정 18개 조문 내 조직 후보 112개의 원문 인용 검증 통과.
- 승인된 국민은행 재분석: needs_review, error_code 없음, organization-v2 / organization 기준, 지적사항 1개·부서 후보 연결 2개·미연결 0개. 비공개 초안 저장까지 확인했으며 게시하지 않았다.
- 수정 코드는 로컬에만 반영됐으므로 GitHub Actions 운영 반영에는 사용자 Commit/Push가 필요하다.
