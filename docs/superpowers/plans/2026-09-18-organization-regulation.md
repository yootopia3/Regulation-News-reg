# 직제규정으로 분석 근거 전환

사용자 요청: 비공개 업무분장규정 대신 제공한 직제규정으로 소관부서 후보를
선정하고, 명시되지 않은 소관업무·점검 포인트는 AI 추정으로 구분한다.
직제규정 자체가 공개 문서인지 확인된 것은 아니므로 원문 비공개 처리를 유지한다.

## 파일 확인 단계 (완료)
- HWP v5 정상, 본문 18개 조문, 과거 부칙 65개 구간.
- 부칙의 반복 제1/2조 때문에 기존 중복 조문 가드가 중단됨.
- 명시적 부칙 이후는 관리자 검토 경고에 보존하고 본문 조문에서는 제외하도록 수정.
  본문 자체의 중복 조문 가드는 유지. 관련 테스트 15개 통과.
- 부서명은 조문 제목이 아니라 제6조 등 본문의 조직 목록에 있음.
  기존 제목→부서 후보 방식으로 바로 교체하면 후보가 0개다.
- 실제 원문을 저장소에 넣지 않고 TEMP의 로컬 검토 HTML을 작성.
- 외부 AI 호출/직제규정 업로드/기존 활성 규정 및 게시 결과 변경은 하지 않음.

## 다음 단계
1. 사용자가 로컬 검토 화면의 조직 목록이 원본/현행 조직과 일치하는지 확인.
2. organization 문서 종류와 검토 가능한 조직명 목록을 별도 구조로 지원.
   기존 조문 한 개=부서 한 개 가정을 그대로 적용하지 않는다.
3. 추론 입력에는 활성 직제규정만 사용, allocation/analysis fallback 금지.
   규정에 명시된 조직·역할과 inferred work를 별도 필드/표식으로 제공.
4. AI 부서 후보는 검토한 조직 목록에서만 선택. 근거 부족은 확인 필요.
5. 직제규정 활성화 때 이전 근거의 작업/게시본 무효화, 재분석 경로 확인.
6. 테스트, 독립 코드 검토, migration→배포→직제규정 등록/검토/활성화 순서로 운영 반영.

아래 진행 기록 기준으로 구현 완료. 운영 DB 적용·배포·직제규정 등록/활성화는 별도 진행한다.

## 2026-09-18 사용자 확인 및 구현 결정
사용자가 로컬 검토 내용이 원본과 일치한다고 확인했다. 조문별 organization_names 배열을 관리자 검토 대상으로 추가한다.
DB 버전 선택과 worker는 organization 종류만 허용한다. 직제규정 조직 목록이 없으면 분석을 중단한다.
조직명을 포함하는 원문 근거는 관리자 초안에만 보관하고, 공개 DTO analysis_basis=organization 표식을 저장/게시/Excel까지 보존한다.
기존 업무규정 분석 함수는 회귀 호환용으로 유지하되 운영 worker는 organization 모드만 호출한다.
새 migration 적용 즉시 기존 기준 결과를 무효화하므로 자동 실행을 끄고 migration→배포→직제규정 등록·검토·활성화→재분석 순서로 반영한다.

## 검증 및 독립 검토
- Python 관련 75개 통과. 실제 첨부 HWP 로컬 파싱: 본문 18조문, 조직 후보 조문 3개/112개 이름, 입력 2,178자.
- PGlite 새 migration 통과: 레거시 결과/게시 무효화, organization-only 버전, 일반 역할 권한 차단,
  원문 없는 이름/공백/중복 거부, 빈 조직 목록 활성화 금지, 삭제 시 작업 무효화.
- 웹 생산 빌드 통과. 기존 Excel 테스트 병렬 부하 시간 초과는 낮춘 병렬 실행에서 통과.
- 독립 SQL 검토: 공백만 있는 조직명 길이 검증 허점 수정 + DB 회귀 통과.
- 독립 분석/게시 검토: 정상 조직명 목록이 원문 복사로 오인되던 문제 수정.
  동일 finding의 검증된 부서명만 허용한 다음 부서 필드만 복사 검사에서 제외.
  요약·업무·점검 문장 복사 검사는 유지. 리뷰어 재검토 해결 확인, 관련 웹 22개 통과.
- 실제 DB 변경, 문서 업로드, 외부 AI 호출, commit/push는 수행하지 않았다.

최종 검증: 웹 전체 144개 통과, Python 관련 75개 통과, DB 통합 스크립트 4개 통과, production build 및 lint 통과. 운영 반영은 미실행.
