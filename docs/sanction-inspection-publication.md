# 검토·게시 및 일반 사용자 점검표

현재 상태: 코드 구현 및 로컬 검증 단계. 운영 migration·기능 활성화·실제 게시는 하지 않았다.

## 관리자 사용 순서

1. `Report → 재제공시 리포트 → 관리자 분석 실행`에서 완료 초안을 연다.
2. 공개용 검토본에서 전체 지적사항의 요약·소관부서·관련 업무·점검 질문·증빙을 검토한다.
   관련 업무는 관리자가 직접 작성하도록 비워 둔다. 미선정 부서는 추가할 수 있다.
3. `검토본 저장`을 누른다. 기존 게시본이 있으면 철회된다.
4. 저장된 내용의 공개 적정성을 확인하고 체크박스를 선택한 뒤 `검토본 게시`를 누른다.
   게시 서버는 지적사항 누락, 공개 페이지, 내부 원문/인용 복사를 다시 검사한다.
5. 공개 화면의 `리포트 조회`에서 게시 결과를 확인한다. `게시 철회`로 내릴 수 있다.

## 일반 사용자 화면

최신 UI에서는 기존 대시보드의 제재공시 카드를 펼친 후 `AI 심층 보고서`를 누른다.
선택한 공시의 요약 브리핑·당행 소관부서·소관업무·점검 포인트·증빙을 모달로 확인하며
원문과 Excel도 같은 창에서 연다. 미게시/운영 비활성 상태에서는 이를 안내한다.
운영 대상: `https://regulation-news-reg-fiu7.vercel.app/`.
아래 별도 페이지는 이전 직접 URL 호환용이며 새 사이드바 진입점에서는 제거했다.

`Report → 재제공시 리포트`의 게시된 점검 리포트에서 조회한다.
한 번에 20건을 읽고 더 보기로 다음 페이지를 불러온다. 각 공시 제목·금감원 원문 링크,
지적사항·요약·소관부서·관련 업무·점검 질문·증빙·공개 PDF 페이지를 제공한다.

Excel 파일은 게시본에서만 생성한다. 출처 공시 제목·공시일·원문 URL도 포함한다.
내부 근거·문서 ID·숨은 시트·수식·Excel 외부 링크 객체는 포함하지 않는다.
표현이 수식처럼 시작해도 문자열 셀로 저장하며 원문 URL도 문자열 셀이다.

## 권한과 공개 경계

- `sanction_publications` 및 검토 행위 이력 테이블은 service_role 전용이다.
  일반 DB 클라이언트에는 테이블/RPC 접근을 허용하지 않는다.
- `/api/sanction-publications`는 기존 서명된 대시보드 세션을 확인한다.
  일반 비밀번호는 관리자 수정·게시 권한을 주지 않는다.
- 게시 JSON은 허용된 필드만 재검증·재구성한다. 내부 문서 인용/파일/원문은 읽지 않는다.
  게시 전 검사만 관리자 서버에서 내부 조문을 페이지네이션으로 읽는다.
- 공개 결과 및 XLSX 응답은 `private, no-store`이며 저장소 파일 URL을 배포하지 않는다.
- 내부 인용 전체, 24자 이상 원문 연속 복사, 일부 필드 분할·공백·구두점 변형을 검사한다.
  이 검사는 재서술된 기밀까지 식별하는 보장이 아니다. 관리자가 전체 공개 범위를 확인한다.
  이미 받은 화면·다운로드 파일은 철회로 소급 삭제할 수 없다.

## 동시 수정·무효화

관리자 검토본은 revision으로 잠근다. 다른 관리자의 저장이나 재분석·규정 변경 뒤의
오래된 화면에서 저장·게시하면 충돌 오류를 반환하며 다시 조회해야 한다.
저장·재분석·규정 변경·삭제는 기존 게시 snapshot을 지운다.
검토 이력에는 내용 없이 작업 ID·행위·revision·관리자 ID·시각만 기록한다.

## 운영 반영

1. 기존 두 migration 다음에 `db/migrations/202609100003_inspection_publications.sql`을 적용한다.
2. 변경 코드를 커밋·푸시해 웹을 배포한다. `exceljs` 의존성과 lockfile을 포함한다.
3. 기존 관리자 인증/내부문서/분석 worker 설정을 완료한다.
4. 웹 서버에 `SANCTION_PUBLICATIONS_ENABLED=true`를 설정하고 재배포한다.
   설정 전에는 일반 조회는 비활성 안내, 신규 게시와 Excel 다운로드는 차단한다.
5. 합성 사례로 관리자 게시·일반 세션 조회·철회·직접 Excel URL 차단을 확인한 뒤
   실제 공시를 분석하고 부서 담당자와 내용 품질을 검토한다.

정지 시 해당 플래그를 false로 바꾸면 신규 게시·일반 조회/내보내기를 막는다.
관리자 철회는 계속 가능하다. 실제 운영 적용과 실제 AI 분석은 별도 검증이 필요하다.
