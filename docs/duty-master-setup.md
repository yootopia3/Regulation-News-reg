# 본부 업무원장 분석 기준 적용

운영 DB·웹·Actions 적용 상태는 배포 시점에 별도로 확인한다.
원장은 부서 소관업무 추정 자료다. 명시/추정/자료 부족과 제재 관련성 판단을 구분한다.
영업조직을 제외하며 실제 업무원장 JSON, 원문 및 조직 자료를 Git 저장소에 추가하지 않는다.

## 적용 순서

1. 기존 문서/분석/게시/자동화/직제규정 migration 이후
   `db/migrations/202609200001_duty_masters.sql`을 적용한다.
   이 migration만으로 기존 결과를 무효화하지 않는다.
2. 새 웹과 worker 코드를 함께 배포한다. 새 웹은 기존 보고서 형식도 지원한다.
   기존 sanction 분석·게시 환경변수 및 외부 AI 전송 정책 확인 설정을 그대로 사용한다.
3. 아래 로컬 명령으로 사용자 지정 JSON을 검사한다. 파일 경로는 실제 보관 위치로 바꾼다.
   보조 근거데이터 JSON 또는 이미 축약한 분석용 JSON을 입력할 수 있다.

   ```sh
   python -m src.services.sanction_inspections.master_import --input /secure/master-source.json --output /secure/master-runtime.json
   ```

   기본 동작은 로컬 변환만 수행한다. 전체 원문과 로컬 경로는 분석용 JSON에서 제외한다.
4. 서버의 기존 Supabase service_role 환경변수를 사용해 `--register`로 비활성 등록한다.
   동일 fingerprint는 기존 ID를 사용한다. 출력에는 버전·해시·건수·ID만 기록한다.
5. 전환 영향을 확인한 뒤 `--register --activate`로 활성화한다.
   **이전 기준의 초안 및 게시본이 무효화되어 화면에서 사라진다.** 이미 실행 중인 이전 버전
   작업의 완료도 거절한다. 필요한 공시의 재분석과 결과 확인까지 묶어서 진행한다.
6. `/admin/inspections`에서 지정 공시를 재분석한다. 관리자 초안에서 업무 ID·출처·역할
   경계를 확인하고, 일반 화면과 Excel에서 부서별 근거 수준과 점검 담당 후보를 확인한다.

## 운영 동작과 한계

### 지정 공시 1건 검증

`202609200002_single_inspection_claim.sql` 적용 후 `Sanction Single Review` workflow를 사용할 수 있다.
전체 자동화 변수를 false로 유지하고 관리자 화면에서 대상 기사만 대기열에 넣는다.
workflow 입력은 해당 article UUID와 활성 원장 fingerprint이며 원장 데이터는 입력하지 않는다.
큐에 다른 queued/processing 작업이 있거나 활성 버전이 달라지면 실행하지 않는다.
대상 확인·claim은 기존 advisory lock 안에서 원자적으로 처리해 다른 작업을 변경하지 않는다.
단건 workflow는 enqueue·자동 게시를 하지 않으며 결과는 관리자 검토 후 게시한다.

- 원장이 활성일 때만 업무원장 경로를 사용한다. 없으면 기존 직제규정 경로다.
- 축약 업무 설명 전체를 한 번 제공한다. 원장 출처 메타데이터는 비공개 관리자 근거에만
  결합하고 AI에는 보내지 않는다. 공개 공시의 사실 추출과 업무원장 연결은 두 단계다.
- AI가 선택한 업무 ID, 같은 부서 여부, 지적사항 처리 여부, 공개 인용과 버전을 검증한다.
  부서별 역할의 의미적 적합성이나 실제 은행의 통제 이행까지 자동 입증하는 검사는 아니다.
- 자료 부족 업무가 포함된 초안은 자동 게시하지 않는다. 미매칭·형식 오류·내부 설명 복사도
  기존 검토 경로로 보낸다. 추정은 추정 표식을 유지한 상태로 기존 자동 게시 정책을 따른다.
- 업무원장을 바꾸려면 새 버전 JSON을 등록한다. 기존 행의 내용은 수정할 수 없다.
- 이전 원장으로 돌아가려면 기존 ID를 활성화 RPC로 선택한다. 직제규정으로 복귀하려면
  service_role 권한으로 활성 원장을 비활성화한다. 두 경우 모두 재분석이 필요하다.
- 활성화 전에 기존 게시본이 필요한지 확인한다. 철회된 snapshot의 내용을 자동 복원하지 않는다.

## 검증

Python 단위 테스트는 원장 형식, 업무 ID/부서/근거 수준, 원문 인용, 버전 및 worker 분기를 검증한다.
웹 테스트는 원장 버전·근거 수준 보존, 편집 시 담당 후보, 공개 projection, Excel,
자료 부족 자동 게시 보류와 기존 보고서 호환성을 검증한다.
`cd web && npm run test:documents-db`에는 원장 권한·불변성·전환·lease 무효화 회귀검사가 포함된다.
실제 운영 AI 품질 검증은 운영 환경에서 별도로 수행해야 한다.
